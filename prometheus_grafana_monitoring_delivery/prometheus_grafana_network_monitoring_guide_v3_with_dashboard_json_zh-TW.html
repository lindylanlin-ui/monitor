Prometheus + Grafana 基礎設施監控系統建置指南

監控 Cisco Switch、FortiGate Firewall、VMware ESXi / VM，並透過 Grafana 發送 Email 與 Telegram 告警。

適合第一次接觸 Prometheus / Grafana / Exporter 的人閱讀。

1. 整體架構

整套系統不只是 Prometheus + Grafana。因為 Cisco、FortiGate、VMware 使用的監控介面不同，所以需要 Exporter 當「翻譯員」。

Cisco Switch ──SNMP──────┐ │ FortiGate ───SNMP───────┼──> SNMP Exporter ─────┐ │ │ │ └──HTTPS API──────────┴──> FortiGate Exporter │ │ ESXi / vCenter ──API────────> VMware/vCenter │ 採集元件 │ ▼ 所有設備 ──Ping/TCP/HTTPS──> Blackbox Exporter -> Prometheus │ ▼ Grafana │ ┌────────────┴───────────┐ ▼ ▼ Email Telegram
白話理解：Exporter 就像翻譯員。Cisco / FortiGate 常講 SNMP，VMware 講 vSphere API，而 Prometheus 只想讀 Prometheus Metrics，所以由 Exporter 幫忙翻譯。

4. Docker Compose vs 一般安裝

項目Docker Compose一般安裝
初次安裝簡單較多步驟
元件管理集中各自管理
版本控制清楚寫在 image tag要記 binary / package 版本
升級pull + up -d逐一升級
Rollback相對容易比較麻煩
設定集中高較分散
搬機容易較麻煩
交接非常適合需要較多 Linux 經驗
Debug OS多一層 Docker較直接
建議：如果是公司內部長期使用，而且未來要交接給其他人，優先使用 Docker Compose。

5.2 compose.yml

services:

  # =========================================================
  # Prometheus
  # 負責定期向所有 Exporter 抓取資料並儲存歷史監控數據
  # =========================================================
  prometheus:
    image: prom/prometheus:v3.13.2
    container_name: prometheus
    restart: unless-stopped

    volumes:
      # Prometheus 主要設定檔
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml:ro

      # Prometheus 歷史監控資料
      - prometheus_data:/prometheus

    command:
      # 指定 Prometheus 設定檔
      - "--config.file=/etc/prometheus/prometheus.yml"

      # 指定資料儲存目錄
      - "--storage.tsdb.path=/prometheus"

      # 保留 30 天監控資料
      - "--storage.tsdb.retention.time=30d"

    ports:
      - "9090:9090"

    networks:
      - monitoring


  # =========================================================
  # SNMP Exporter
  # 負責向 Cisco / FortiGate 等 SNMP 設備抓資料
  # =========================================================
  snmp-exporter:
    image: prom/snmp-exporter:v0.30.1
    container_name: snmp-exporter
    restart: unless-stopped

    ports:
      - "9116:9116"

    networks:
      - monitoring


  # =========================================================
  # Blackbox Exporter
  # 負責 Ping / TCP / HTTP / HTTPS 可用性檢查
  # =========================================================
  blackbox-exporter:
    image: prom/blackbox-exporter:v0.28.0
    container_name: blackbox-exporter
    restart: unless-stopped

    volumes:
      - ./blackbox/blackbox.yml:/etc/blackbox_exporter/config.yml:ro

    # ICMP Ping 需要 RAW Socket 權限
    cap_add:
      - NET_RAW

    ports:
      - "9115:9115"

    networks:
      - monitoring


  # =========================================================
  # FortiGate Exporter
  # 使用 FortiGate HTTPS API 取得較完整的防火牆資訊
  # =========================================================
  fortigate-exporter:
    image: prometheuscommunity/fortigate-exporter:v1.25.0
    container_name: fortigate-exporter
    restart: unless-stopped

    volumes:
      # FortiGate API Token 設定
      - ./fortigate/fortigate-key.yml:/config/fortigate-key.yml:ro

    command:
      - "-auth-file"
      - "/config/fortigate-key.yml"

    networks:
      - monitoring


  # =========================================================
  # Grafana
  # Dashboard + Alerting
  # =========================================================
  grafana:
    image: grafana/grafana:13.2.0
    container_name: grafana
    restart: unless-stopped

    ports:
      - "3000:3000"

    environment:
      # Grafana 初始管理員帳號
      GF_SECURITY_ADMIN_USER: ${GRAFANA_ADMIN_USER}
      GF_SECURITY_ADMIN_PASSWORD: ${GRAFANA_ADMIN_PASSWORD}

      # -----------------------------------------------------
      # SMTP Mail 設定
      # -----------------------------------------------------
      GF_SMTP_ENABLED: "true"

      # SMTP Server，例如公司 Mail Server
      GF_SMTP_HOST: ${SMTP_HOST}

      # SMTP 登入帳號
      GF_SMTP_USER: ${SMTP_USER}

      # SMTP 密碼
      GF_SMTP_PASSWORD: ${SMTP_PASSWORD}

      # 告警寄件人
      GF_SMTP_FROM_ADDRESS: ${SMTP_FROM_ADDRESS}

      # 寄件人顯示名稱
      GF_SMTP_FROM_NAME: "Grafana Monitoring"

    volumes:
      # Grafana Database / Dashboard / Alert 設定
      - grafana_data:/var/lib/grafana

      # Grafana Provisioning 設定
      # 包含 Datasource 與 Dashboard Provider
      - ./grafana/provisioning:/etc/grafana/provisioning:ro

      # Dashboard JSON 來源檔，必須納入 Git 版控
      # :ro 代表 Container 只讀，避免正式環境直接改壞來源檔
      - ./grafana/dashboards:/var/lib/grafana/dashboards:ro

    networks:
      - monitoring


# =========================================================
# Docker Persistent Volume
# Container 刪掉後資料仍然存在
# =========================================================
volumes:
  prometheus_data:
  grafana_data:


# =========================================================
# 監控系統專用 Docker Network
# =========================================================
networks:
  monitoring:
    driver: bridge

6. Prometheus 設定

檔案：prometheus/prometheus.yml

# =========================================================
# Prometheus 全域設定
# =========================================================
global:

  # 每 30 秒抓一次監控資料
  scrape_interval: 30s

  # 每 30 秒重新計算 Alert Rule
  evaluation_interval: 30s


scrape_configs:

  # =======================================================
  # Prometheus 自己
  # =======================================================
  - job_name: "prometheus"

    static_configs:
      - targets:
          - "prometheus:9090"


  # =======================================================
  # Cisco Switch
  #
  # if_mib：
  #   Port、流量、Error、Discard、Speed 等
  #
  # system：
  #   Uptime、Device Description 等
  #
  # cisco_device：
  #   Cisco CPU、Memory、Sensor、Power 等
  # =======================================================
  - job_name: "cisco-switch"

    metrics_path: /snmp

    params:
      # 教學範例使用 SNMP v2
      # 正式環境建議改 SNMP v3
      auth:
        - public_v2

      module:
        - if_mib
        - system
        - cisco_device

    static_configs:
      - targets:
          # Core Switch
          - "192.168.10.10"

          # Access Switch
          - "192.168.10.11"
          - "192.168.10.12"

    relabel_configs:
      # 把設備 IP 傳給 SNMP Exporter
      - source_labels:
          - __address__
        target_label: __param_target

      # Grafana / Prometheus 顯示真正的設備 IP
      - source_labels:
          - __param_target
        target_label: instance

      # 實際請求 SNMP Exporter
      - target_label: __address__
        replacement: snmp-exporter:9116


  # =======================================================
  # FortiGate Port SNMP
  # =======================================================
  - job_name: "fortigate-snmp"

    metrics_path: /snmp

    params:
      auth:
        - public_v2

      module:
        - if_mib
        - system

    static_configs:
      - targets:
          - "192.168.20.1"

    relabel_configs:
      - source_labels:
          - __address__
        target_label: __param_target

      - source_labels:
          - __param_target
        target_label: instance

      - target_label: __address__
        replacement: snmp-exporter:9116


  # =======================================================
  # FortiGate API Exporter
  # =======================================================
  - job_name: "fortigate-api"

    metrics_path: /probe

    static_configs:
      - targets:
          - "https://192.168.20.1"

    relabel_configs:
      - source_labels:
          - __address__
        target_label: __param_target

      - source_labels:
          - __param_target
        target_label: instance

      - target_label: __address__
        replacement: fortigate-exporter:9710


  # =======================================================
  # Ping Monitoring
  # =======================================================
  - job_name: "ping"

    metrics_path: /probe

    params:
      module:
        - icmp

    static_configs:
      - targets:
          # Cisco
          - "192.168.10.10"
          - "192.168.10.11"

          # FortiGate
          - "192.168.20.1"

          # ESXi
          - "192.168.30.11"
          - "192.168.30.12"

          # vCenter
          - "192.168.30.10"

    relabel_configs:
      - source_labels:
          - __address__
        target_label: __param_target

      - source_labels:
          - __param_target
        target_label: instance

      - target_label: __address__
        replacement: blackbox-exporter:9115

7. Blackbox Exporter 設定

檔案：blackbox/blackbox.yml

modules:

  # =======================================================
  # ICMP Ping
  # =======================================================
  icmp:

    # 使用 ICMP
    prober: icmp

    # 最多等待 5 秒
    timeout: 5s


  # =======================================================
  # TCP Port 測試
  #
  # 例如：
  # SSH 22
  # HTTPS 443
  # =======================================================
  tcp_connect:

    prober: tcp

    timeout: 5s


  # =======================================================
  # HTTPS Monitoring
  # =======================================================
  https_2xx:

    prober: http

    timeout: 10s

    http:
      # 只接受 HTTP 2xx
      valid_status_codes:
        - 200
        - 201
        - 202
        - 204

      # 優先 IPv4
      preferred_ip_protocol: ip4

8. Grafana 自動建立 Prometheus Datasource

檔案：grafana/provisioning/datasources/prometheus.yml

apiVersion: 1

datasources:

  # =======================================================
  # Prometheus Datasource
  # Grafana 啟動後會自動建立
  # =======================================================
  - name: Prometheus

    # Datasource 類型
    type: prometheus

    # 固定 Datasource UID
    # Dashboard JSON 會引用這個 UID，讓不同 Grafana 環境都能穩定找到 Prometheus
    uid: prometheus

    # Grafana Server 直接連 Prometheus
    access: proxy

    # Docker Compose 內直接使用 Service Name
    url: http://prometheus:9090

    # 設成預設 Datasource
    isDefault: true

    editable: true

9. Grafana Dashboard 版控（Dashboard as Code）

前一版缺少的就是這一層。
如果 Dashboard 只在 Grafana Web UI 裡建立，它主要存在 Grafana Database 中；即使 compose.yml 與 Prometheus 設定都有進 Git，也不能完整重建監控畫面。

9.1 正確的版控架構

Git Repository │ ├── compose.yml ├── prometheus/ ├── blackbox/ └── grafana/ ├── provisioning/ │ ├── datasources/prometheus.yml │ └── dashboards/dashboards.yml └── dashboards/ ├── Network/ │ ├── cisco-switch-overview.json │ └── fortigate-overview.json └── VMware/ ├── esxi-overview.json └── vm-overview.json │ ▼ Docker bind mount │ ▼ /var/lib/grafana/dashboards │ ▼ Grafana Provisioning │ ▼ Dashboards

這樣 Git 才是真正的 Source of Truth。

9.2 Dashboard Provider

建立 grafana/provisioning/dashboards/dashboards.yml：

apiVersion: 1

providers:

  # =======================================================
  # Git 版控 Dashboard Provider
  # =======================================================
  - name: "version-controlled-dashboards"

    # 一般單一 Organization 使用 1
    orgId: 1

    # Dashboard 從本機檔案讀取
    type: file

    # Git / 檔案刪除 Dashboard 時，允許 Grafana 同步刪除
    disableDeletion: false

    # 30 秒輪詢 Dashboard JSON
    # Docker bind mount 某些環境的 filesystem watch event 不一定能傳進 Container；
    # 大於 10 秒會使用 polling，較適合這種掛載方式。
    updateIntervalSeconds: 30

    # 正式環境禁止直接在 Grafana UI 儲存修改
    # 避免 UI 已改、Git JSON 沒改，造成兩邊不一致
    allowUiUpdates: false

    options:
      # Container 內 Dashboard JSON 的位置
      path: /var/lib/grafana/dashboards

      # 依實體資料夾建立 Grafana Folder
      foldersFromFilesStructure: true
使用 foldersFromFilesStructure: true 時，不要另外設定 provider 的 folder 或 folderUid。

9.8 為什麼 Production 設 allowUiUpdates: false？

Git JSON                 Production Grafana UI
   │                              │
CPU Warning = 80%          某人改成 90%
   │                              │
   └──────────── 不一致 ───────────┘

下一次 provisioning 套用檔案時，Git 裡的內容仍可能覆蓋 Database 裡的 UI 修改。因此正式環境要把 Git 當唯一來源。

9.9 Dashboard JSON 更新後要 restart 嗎？

Dashboard JSON 本身通常不用 restart；provider 會依 updateIntervalSeconds 重新掃描。若修改 provider YAML、compose.yml 或 Grafana 環境變數，再重新建立 Grafana：

docker compose up -d grafana

10. Grafana Git Sync（選配，Grafana 13.x）

Grafana 13.x 也提供 Git Sync。如果希望直接在 Grafana UI 修改 Dashboard，並把變更同步回 Git 或建立 PR/MR，可以評估 Git Sync。

Grafana UI │ ▼ Grafana Git Sync ─────> Git Commit / PR ▲ │ └───────────────────────┘
項目File Provisioning + GitGit Sync
Git 為 Source of Truth是是
初學者設定難度較低較高
UI 修改自動回 Git否是
Production Read-only很容易做到依權限 / workflow 設計
Git CredentialGrafana 不需要 Git 寫入權限Grafana 需連 Git Provider
本教學主線建議先用 File Provisioning + Git。
結構更單純、容易交接，也符合「改 JSON → Git Review → Deploy」的正式維運流程。日後需要直接從 Grafana UI 走 Git workflow 時，再升級成 Git Sync。

若公司使用 GitLab 且 Grafana 為 OSS，可評估 Grafana 的 Pure Git repository 類型連接 GitLab；Token 等 Git 憑證不要寫進 Repository。

12. Cisco Port 流量怎麼計算？

ifHCInOctets 是累積 Byte，不是 Mbps，所以要用 rate() 算每秒增加量。

RX bit/s

rate(ifHCInOctets[5m]) * 8

TX bit/s

rate(ifHCOutOctets[5m]) * 8

轉 Mbps

rate(ifHCInOctets[5m]) * 8 / 1000000

計算 Port 使用率 %

(
  rate(ifHCInOctets[5m]) * 8
)
/
(
  ifHighSpeed * 1000000
)
* 100
對 1 Gbps / 10 Gbps 等高速介面，應優先使用 64-bit counter，例如 ifHCInOctets / ifHCOutOctets。

13. Grafana 告警設計

項目WarningCritical
Device Down-持續 2 分鐘
Important Port Down-持續 1 分鐘
Port Utilization>80% 10m>90% 5m
CPU>80% 10m>90% 5m
Memory>85% 10m>95% 5m
Ping-Fail 2m
Packet Loss>2%>5%
Datastore Free<15%<10%
VPN Tunnel-Down 2m
ESXi Host-Down 2m
不要把所有 Access Port Down 都送告警。使用者關電腦就會一直告警。真正值得告警的是 Uplink、Trunk、Firewall Port、WAN、Server Port、ESXi Port、Core Link、Port-channel。

Dashboard Threshold 與 Alert Rule 不一樣

Dashboard Threshold 只是讓 Panel 顏色變色；真正會發通知的是 Alert Rule。

Prometheus Query ↓ Grafana Expression ↓ Threshold ↓ For 5 minutes ↓ Alert FIRING ↓ Contact Point ↓ Email + Telegram

設備 Down 告警範例

up{job="cisco-switch"}

正常 = 1，異常 = 0。Grafana 可設定：

WHEN
up
IS BELOW
1

Pending period:
2m

  1. 在 Telegram 找 BotFather
  2. 輸入 /newbot
  3. 建立 Bot
  4. 取得 Bot API Token
  5. 取得 Chat ID
  6. Grafana → Alerting → Contact points → Add contact point
  7. 選擇 Telegram
  8. 填入 Bot Token 與 Chat ID
  9. 按 Test 測試

16. 一般安裝方式

不用 Docker 時，每一個元件都直接跑在 Linux 上，通常交給 systemd 管理：

Linux │ ├─ prometheus process ├─ grafana-server process ├─ snmp_exporter process ├─ blackbox_exporter process └─ fortigate_exporter process 全部交給 systemd

16.1 Prometheus

sudo useradd \
  --system \
  --no-create-home \
  --shell /usr/sbin/nologin \
  prometheus

sudo mkdir -p /etc/prometheus
sudo mkdir -p /var/lib/prometheus

下載並安裝 binary：

wget https://github.com/prometheus/prometheus/releases/download/v3.13.2/prometheus-3.13.2.linux-amd64.tar.gz

tar xvf prometheus-3.13.2.linux-amd64.tar.gz

sudo cp prometheus-3.13.2.linux-amd64/prometheus /usr/local/bin/
sudo cp prometheus-3.13.2.linux-amd64/promtool /usr/local/bin/

/etc/systemd/system/prometheus.service

[Unit]

# Prometheus Service 說明
Description=Prometheus Monitoring Server

# 等網路啟動完成
After=network-online.target


[Service]

# 使用 prometheus 帳號執行
User=prometheus
Group=prometheus

# Prometheus 執行檔
ExecStart=/usr/local/bin/prometheus \
  --config.file=/etc/prometheus/prometheus.yml \
  --storage.tsdb.path=/var/lib/prometheus \
  --storage.tsdb.retention.time=30d

# 程式異常時自動重新啟動
Restart=on-failure


[Install]

# 開機自動啟動
WantedBy=multi-user.target

啟動：

sudo systemctl daemon-reload
sudo systemctl enable --now prometheus

systemctl status prometheus
journalctl -u prometheus -f

16.2 SNMP Exporter

wget https://github.com/prometheus/snmp_exporter/releases/download/v0.30.1/snmp_exporter-0.30.1.linux-amd64.tar.gz

systemd 概念：

[Unit]
Description=Prometheus SNMP Exporter
After=network-online.target

[Service]

# 使用專用帳號
User=snmp-exporter

# 啟動 SNMP Exporter
ExecStart=/usr/local/bin/snmp_exporter \
  --config.file=/etc/snmp_exporter/snmp.yml

Restart=on-failure

[Install]
WantedBy=multi-user.target

16.3 常見設定位置

/etc/grafana/grafana.ini
/etc/prometheus/prometheus.yml
/etc/snmp_exporter/snmp.yml
/etc/blackbox_exporter/blackbox.yml
一般安裝的優點是服務直接跑在 OS 上，比較容易追 systemd / journal；缺點是元件多時，升級、版本控管、搬機與交接比較麻煩。

Phase 1：監控平台

  • Prometheus
  • Grafana
  • SNMP Exporter

  • Device UP / DOWN
  • Ping
  • CPU
  • Memory
  • Temperature
  • Port UP / DOWN
  • RX / TX
  • Bandwidth %
  • Error / Discard

Phase 3：FortiGate

  • CPU / Memory / Sessions
  • Port / WAN
  • HA
  • VPN
  • SD-WAN
  • License

Phase 4：VMware

  • ESXi Host
  • VM
  • Datastore
  • Snapshot

Phase 5：Alert

建議至少區分兩級：

severity="warning"

severity="critical"
最推薦的實作順序：
一台全新的 Linux 主機 → 安裝 Docker → 建立 /opt/monitoring → 啟動 Prometheus / Grafana → 接第一台 Cisco Switch → 先確認 Port Traffic、CPU、Memory、溫度真的進到 Grafana，再逐步擴充 FortiGate 與 VMware。
